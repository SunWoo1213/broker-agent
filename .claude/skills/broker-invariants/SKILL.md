# 불변 원칙 → 코드 패턴

원칙 원문은 `CLAUDE.md`에 있다. 이 문서는 "코드에서 어떻게 보이는가"만 다룬다.

## 원칙 1. fail-closed

| 금지 | 올바름 |
|---|---|
| `except Exception: return Decision.ALLOW` | 예외 → `deny` + reason(`"opa_unreachable"` 등) |
| `decision = resp.get("result", "allow")` | 기본값은 항상 `deny`. 키가 없으면 거부 |
| `if settings.DEV: skip_policy()` 같은 우회 플래그 | 개발 편의는 가짜 OPA(테스트 더블)로. 운영 코드 경로에 우회 분기 없음 |
| 타임아웃 없는 외부 호출 | 모든 OPA · DB · Redis 호출에 타임아웃. 타임아웃 = 거부 |
| `if decision != "deny": call_tool()` | `if decision == "allow": ...` 허용을 명시적으로 확인 |

## 원칙 2. 에이전트는 실제 자격 증명을 보지 못한다

- 도구 응답 · 오류 메시지 · 로그에 실제 API 키, DB 비밀번호, 내부 주소가 섞여 에이전트에게 돌아가면 위반
- 도구 서버는 브로커 토큰만 검증한다. 에이전트 키로 도구를 직접 부를 수 있으면 위반
- 토큰 클레임: 도구, 작업, 인자 해시, 만료(≤5분), 1회성 식별자(jti)

## 원칙 3. 승인은 인자 해시에 묶인다

- 해시는 **정규화된** 인자로 계산한다 (키 정렬, 공백 · 숫자 표현 고정). 정규화 없이 `str(dict)` 해시는 위반
- 실행 직전에 재계산해서 승인 레코드의 해시와 비교. 비교는 `hmac.compare_digest`
- 승인 상태 전환은 `docs/architecture.md` 3절 그림에 있는 것만. DB 제약 + 코드 양쪽

## 원칙 4. 누적 한도는 예약 → 확정 / 해제

| 금지 | 올바름 |
|---|---|
| `remaining = get(); if remaining >= amt: decr(amt)` | Redis Lua 한 번에 확인 + 예약 |
| 실행 실패 시 예약을 그대로 둠 | `finally`에서 해제, 성공 시 확정 |
| 승인 만료 시 예약 방치 | 만료 처리에서 예약 해제 |

## 원칙 5. 모든 판단은 감사 로그에 남는다

- 판단 결과 저장과 `outbox` INSERT는 **같은 트랜잭션**. 커밋 후 별도로 이벤트 발행은 위반
- 거부 · 오류 경로도 기록한다. 허용만 기록하면 위반
- 감사 레코드: 사용자, 에이전트, 작업, 인자 해시, 판단, 이유, 정책 버전

## 원칙 6. 취소는 즉시 반영된다

- 캐시 키에 위임 버전을 포함하거나, 캐시 값의 버전을 Pub/Sub 알림과 대조
- TTL만으로 취소를 처리하면 위반 (TTL 동안 취소된 권한이 살아 있음)
- Pub/Sub 연결이 끊기면 캐시를 믿지 않는다 (원칙 1과 결합)

## 원칙 7. 평가 수치는 재현 가능해야 한다

- 시나리오 · 채점 기준 · 기대값을 결과를 본 뒤 고치면 위반
- 실행 조건(시드, 모델, 설정 버전)을 결과와 함께 기록
