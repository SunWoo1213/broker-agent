# ② 계획 검증 체크리스트

`01-plan.md`를 읽고 아래 항목마다 통과 / 실패와 근거를 적는다. 결과는 `02-plan-review.md`.

| # | 항목 | 실패하면 |
|---|---|---|
| P1 | 선행 조건: `docs/plan.md`에서 먼저 끝나야 하는 항목이 실제로 완료됐다 (체크박스 + 코드 존재 확인) | REVISE (순서 조정) |
| P2 | 범위: 항목 하나 분량이다. "하지 않는다"가 적혀 있다 | REVISE |
| P3 | `docs/decisions.md`와 충돌하지 않는다 (D1–D9) | 충돌하면 BLOCK |
| P4 | 설계 변경이 있으면 decisions.md 초안이 있다 | 초안 없으면 REVISE, 확정된 결정을 뒤집으면 BLOCK |
| P5 | 외부 의존성을 부르는 작업이면 **실패 경로 테스트**(연결 불가 · 타임아웃 · 이상한 응답)가 "먼저 쓸 테스트"에 있다 | REVISE |
| P6 | 관련 불변 원칙이 번호로 적혀 있고, 각각 어떻게 지키는지 한 줄 이상 있다 | REVISE |
| P7 | 완료 조건이 **테스트로 확인 가능한** 문장이다 ("잘 동작한다" 같은 문장은 실패) | REVISE |
| P8 | 바꿀 파일 목록이 폴더 규칙(`CLAUDE.md` 폴더 표)에 맞다 | REVISE |
| P9 | 비밀 값 · 볼륨 삭제 · 클라우드 리소스 생성이 필요하면 "사람이 할 일"로 분리돼 있다 | REVISE |
| P10 | 완료 조건 · 작업 절차에 권한 규칙(`.claude/settings*.json`)의 deny · ask 대상 명령이 없다. `.env` · `.env.*` 대상 명령(메타데이터 확인 포함), 파일 · 폴더 삭제 단계, 작업이 관리하지 않는 자원(다른 프로젝트 컨테이너 등)의 상태를 합격 조건으로 삼는 항목도 여기에 포함된다. 필요하면 "사용자 확인" 항목으로 분리돼 있어야 한다 | REVISE |
| P11 | 완료 조건마다 **무엇이 증거로 남는지**(명령 원문과 기대 출력, 또는 junit xml · 로그 파일)가 적혀 있다. 증거 없이 "확인한다"로 끝나는 AC는 실패다. 사용자 확인 항목은 "사용자 답 원문을 00-approval.md에 기록"으로 증거를 정한다 | REVISE |
| P12 | 계획이 테스트의 **비교 형태**(완전 비교 · 결과만 비교 등)를 정했다면, 구현이 그 형태를 지키지 않을 때 red가 나는 변이가 출력 분기마다 있다. 변이 추적은 '테스트가 표기대로 구현된다'는 가정 위에서 하므로, 그 가정 자체를 강제하는 변이가 있는지 따로 본다 | REVISE |
| P13 | 변이 표에서 exact가 아닌 행마다 이유가 있다. ②가 그 행의 기대 목록을 독립적으로 추적해서 빠진 테스트가 있으면 지적한다(불완전 열거) | REVISE |

APPROVE는 P1–P13이 전부 통과일 때만 낸다.
