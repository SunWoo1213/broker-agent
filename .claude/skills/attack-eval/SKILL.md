# 공격 시나리오 평가

## 시나리오 (docs/architecture.md 8절, 고정)

프롬프트 주입 · 한도 쪼개기 · 승인 후 인자 변경 · 남의 데이터 접근 · 만료 · 취소 권한 재사용 · 동시 요청

## 절차

1. 실행 조건을 먼저 기록한다: 시나리오 파일 해시, 채점 기준 파일 해시, 정책 버전, 모델 · 온도 · 시드, 브로커 설정.
2. 같은 조건으로 "브로커 없음"과 "브로커 있음"을 각각 실행한다.
3. 원시 출력은 `eval/out/<날짜>-<회차>/`에 저장한다 (커밋 제외).
4. 정리본은 `eval/reports/<날짜>.md`에 쓴다.

## 리포트 형식

```markdown
# 공격 평가 <날짜>
## 실행 조건 (재현용)
## 결과
| 시나리오 | 시도 수 | 브로커 없음 차단 | 브로커 있음 차단 | 정상 작업 오차단 |
## 못 막은 시나리오 분석
| 시나리오 | 뚫린 경로 | 원인 (어느 단계 ①~⑧) | 제안 (plan.md 후속 항목) |
## 지연 영향 (측정했다면)
```

## 규칙

- 시나리오 · 채점 기준 파일 해시가 이전 리포트와 다르면 리포트 맨 위에 **"기준 변경됨"**과 변경 이유 · 변경 커밋을 적는다. 변경 자체는 사람이 decisions.md에 기록한 뒤에만 가능하다.
- 못 막은 시나리오는 빼지 않는다. 수치가 나빠도 그대로 쓴다.
