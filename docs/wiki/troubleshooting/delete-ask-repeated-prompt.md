# 임시 폴더 삭제가 ask 규칙에 걸려 확인 요청이 반복됨

| 발생일 | 분류 | 상태 | 발견 경로 | 관련 원칙 |
|---|---|---|---|---|
| 2026-09-24 | 하네스 | 해결 (사용자 정책 결정) | ⑤ 테스트 실행 중 | — (권한 설정 유지 결정) |

## 증상

⑤ 테스트(test-verifier)가 완료 조건 AC5(저장소 밖 임시 venv 설치 확인 후 삭제)를 수행하는 중, 삭제 단계(`rm -rf` / `Remove-Item -Recurse -Force`)가 `.claude/settings.local.json`의 삭제 ask 규칙에 걸려 사람 확인 요청이 반복됐다.

## 재현 방법

1. AC에 "확인 후 임시 폴더만 지운다"처럼 삭제 단계가 들어 있고
2. `settings.local.json`에 재귀 삭제가 ask로 설정되어 있으면
3. 같은 작업(구현 ③, 테스트 ⑤)에서 삭제를 두 번(또는 그 이상) 실행하게 되어 확인 요청이 매번 뜬다.

## 원인

1. 직접 원인: AC5가 임시 산출물 삭제를 완료 조건 절차 자체에 포함했다.
2. 왜? → planner가 "확인 후 정리"를 계획의 일부로 넣는 것을 당연하게 여겼고, 삭제가 ask 규칙과 부딪힐 수 있다는 것을 고려하지 않았다.
3. 근본 원인: 완료 조건(AC)은 "무엇이 참인지 확인"하는 것이지 "무엇을 정리하는지"는 별개인데, 계획 형식이 둘을 섞어서 매 실행마다 사람 확인이 필요한 절차가 반복 재생됐다.

## 해결

사용자가 두 선택지 중 정책을 선택했다:
- (선택하지 않음) 삭제 ask 규칙을 완화한다.
- **(선택함)** 권한 설정은 그대로 두고, 계획에서 삭제 단계 자체를 뺀다. 임시 산출물은 "삭제하지 않고 경로만 기록"한다.

반영:
- `agents/planner.md:72` "하지 말 것"에 추가: AC·절차에 삭제 단계를 넣지 않고, 임시 산출물은 경로만 기록한다.
- `05-test-report.md`: AC5에서 확인·`pip check`만 하고 `C:\Users\swsj1\AppData\Local\Temp\broker-venv-check-05` 삭제는 시도하지 않음. "정리는 사용자가 직접 함"으로 05 결과와 `06-improvement-plan.md`의 "사용자 할 일"에 경로를 남김.

## 검증

`07-improvement-review.md` I3·I6: `planner.md:72`에 실제로 문장이 들어갔음을 확인. `05-test-report.md`의 AC5가 삭제 없이 경로 기록으로 처리됐고, 이를 "기준 완화"가 아니라 "사람 정책 결정"으로 판정(07 "기준 완화 탐지" 표).

## 재발 방지

- `planner.md:72` 규칙 추가로 향후 계획에는 삭제 단계 자체가 들어가지 않는다.
- 정리가 필요한 임시 산출물은 03·05 문서에 경로만 남기고, 실제 삭제는 사용자가 판단해 직접 한다.
