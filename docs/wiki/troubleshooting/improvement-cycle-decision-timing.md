# 개선 사이클에서 사용자 승인된 설계 결정(decisions.md) 반영을 "마무리"로 미룸

> 요약
> - 한 줄 해결: 사용자 확인(K10 등)을 받은 설계 결정은 다음 구현(③) 시작 **전에** 메인 세션이 `docs/decisions.md`에 반영하고, 같은 시각 `00-approval.md` "작업 중 사람이 한 변경" 표에 백틱 전체 경로로 기록한다. "마무리까지 미룬다"는 선택지가 아니다.
> - 원인: 개선 계획(⑥ 담당)이 "AC6(범위 검사)의 해시 보호"를 "고치면 안 되는 이유"로 잘못 읽었다. 실제로는 `00-approval.md` 표 기록으로 HUMAN 처리되도록 설계된 장치였다.
> - 재발 방지: `agents/planner.md` ⑥ 개선 모드에 "개선 사이클에서 설계 결정이 바뀌면 사용자 승인 직후·다음 ③ 전에 반영한다. 범위 AC의 해시 보호는 미룰 이유가 아니라 00-approval.md 표에 기록할 대상이다" 추가 제안(H8, 사용자 결정 대기).

## 증상

개선 사이클1의 `06-improvement-plan.md`(1차)는 `mail.send` subject·body 필수화를 D18 계약으로 승격하는 것(K10, A안)을 사용자가 승인하면, 그 문구를 `docs/decisions.md`에 반영하는 일을 **"마무리 때(⑦ APPROVE 뒤)"**로 미뤘다. 즉 개선 사이클2(③–⑤)가 진행되는 동안 계약 문서(D18)는 정책·테스트보다 느슨한 상태로 남아 있을 예정이었다.

## 재현 방법

1. 개선 계획(⑥)이 설계 결정 변경(K10 같은 사용자 확인)을 포함한다.
2. "AC6(`ac_scope.py`)이 `docs/decisions.md`를 보호 파일로 해시 대조한다"는 이유로, ⑥이 그 결정의 반영을 사이클 종료 후로 미룬다.
3. ⑦(검토)이 `work-item/SKILL.md`·`CLAUDE.md`의 순서 규칙과 대조하면 어긋남이 드러난다.

## 원인

1. 직접 원인: `06-improvement-plan.md`(1차)의 "(b) 권장안 — 누가·언제" 절이 decisions.md 반영을 "마무리"로 배치했다.
2. 왜? → ⑥이 "AC6 rule4(보호 파일 해시)가 `docs/decisions.md`를 대조하므로, 사이클 도중에 고치면 BAD가 난다"고 판단해 아예 손대지 않으려 했다.
3. 왜 틀렸나? → 이 판단은 두 가지를 놓쳤다. 첫째, `work-item/SKILL.md:81`("③–⑤ 동안 메인 세션 추적 파일 수정 금지")은 ③ **시작 전**에 고치는 것을 막지 않는다. 둘째, AC6 rule4의 해시 보호는 `00-approval.md` "작업 중 사람이 한 변경" 표에 백틱으로 감싼 전체 경로를 적으면 `ac_scope.py`가 HUMAN으로 인정해 통과시키도록 이미 설계돼 있다(사이클1 ⑤에서 작업 B 마무리 문서 6개가 같은 방식으로 통과했다).
4. 근본 원인: `work-item/SKILL.md:67`("승인받으면 메인 세션이 decisions.md에 추가한 뒤 ③으로")과 `CLAUDE.md`("설계를 바꾸는 결정은 코드보다 먼저 decisions.md에")가 이미 순서를 정하고 있었는데, ⑥이 이를 계획 승인(01단계) 때의 규칙으로만 여기고 **개선 사이클에도 같은 규칙이 적용된다**는 것을 놓쳤다.

## 해결

`06-improvement-plan.r2.md`에서 순서를 다음과 같이 교정했다.

> **⑦ r2 APPROVE → K10 사용자 확인 → decisions.md D18 보강 + 00-approval.md 기록(같은 시각) → 사이클2 ③.**

1. K10(A안) 승인 직후, `00-approval.md` 머리 부분에 승인 줄과 "작업 중 사람이 한 변경" 표에 `` `docs/decisions.md` `` 행(시각·사용자 답 원문 포함)을 추가한다.
2. **같은 시각**, 메인 세션이 `docs/decisions.md` "D18 상세"의 문장 하나만 교체한다(교체 전 문장이 파일에 글자 그대로 없으면 멈추고 보고).
3. 사이클2 `build-c2-env`가 `grep -n "K10" docs/decisions.md`와 `grep -n "K10(A" 00-approval.md`로 두 조건이 모두 있는지 확인하고, 하나라도 비면 ③을 멈춘다.
4. D18 **표 줄**의 "검증" 칸 숫자(53→54개, 21→25종)처럼 사이클2가 끝나야 사실이 되는 수치는 마무리에 남긴다.

## 검증

- ⑦ r3(사이클1 최종)에서 `00-approval.md`에 `K10(A` 문자열이 0건임(사용자 승인 전 상태)을 직접 확인해 grep 패턴이 표 행에만 반응함을 검증했다.
- 사이클2 ⑤ AC6(로그 261)에서 `HUMAN rule4: protected files unchanged: 'docs/decisions.md'` 정확히 1줄이 나왔고, `00-approval.md`의 해당 표 행 시각(19:36)이 `build-c2-env` 시각(19:38:16)보다 앞임을 확인해 "결과를 본 뒤 표를 채운 것"이 아님을 증명했다.

## 재발 방지

- `agents/planner.md` ⑥ 개선 모드(제안, H8): "개선 사이클에서 설계 결정(decisions.md)이 바뀌면, 사용자 승인 직후·다음 ③ 전에 메인 세션이 고치도록 계획한다. 범위 AC의 해시 보호는 '미룰 이유'가 아니라 `00-approval.md` 표에 기록할 대상이다."
